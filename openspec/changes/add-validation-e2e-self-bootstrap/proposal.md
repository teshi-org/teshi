## Why

The validation change has unit and integration coverage, but its acceptance Feature files are currently prose-only and are not executed by `teshi run`. That leaves the CLI validation and execution gates without a black-box test of the built Teshi binary, so the project cannot yet verify this capability through its own BDD workflow.

## What Changes

- Add an independent NDJSON validation runner that launches the exact Teshi binary under test as a child process.
- Add paired English and Chinese executable CLI Features covering source diagnostics, check scopes, JSON output, warnings, binding gates, run gates, and replay gates.
- Keep malformed Feature source as isolated test data generated by the runner, so the executable test specification itself remains valid.
- Add a CI/local integration entry point that builds the runner and executes the paired Features through `teshi run`.
- Document the self-bootstrap boundary: Feature replay validates black-box CLI behavior, while lower-level parser/editor contracts remain covered by Rust tests.

## Capabilities

### New Capabilities

- `validation-e2e-self-bootstrap`: Executable, isolated, bilingual black-box coverage for the Gherkin validation command and its binding/execution gates.
